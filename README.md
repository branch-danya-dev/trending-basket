# trending-basket

Личный фоновый торговый бот для линейных USDT-перпетуалов Bybit. Горизонт решений — 4 часа и 1 день, позиции держатся от дней до недель.

**Статус: в разработке. Бот не торгует реальными деньгами.** Режим `live` запрещён кодом до отдельной задачи (см. `docs/ROADMAP.md`).

## Быстрый старт

### Windows (PowerShell)

```powershell
uv sync
uv run tb --help
uv run tb doctor
uv run pytest
```

### Linux

```bash
uv sync
uv run tb --help
uv run tb doctor
uv run pytest
```

## Вселенная символов

Из корня репозитория, одинаково на Windows и Linux:

```text
uv run tb data sync instruments
uv run tb universe candidates --out data/universe/candidates.txt
uv run tb data sync klines --symbols-file data/universe/candidates.txt --interval 1d --since 2021-01-01
uv run tb universe build --name core15 --since 2021-01-01
uv run tb universe report core15
uv run tb universe show core15 --at 2024-03-01
```

По умолчанию — 15 монет, минимум 120 записанных дневных свечей, медианный
оборот за полные предыдущие 30 дней от 10 млн. Параметры: `--top`,
`--min-history-days`, `--turnover-window`, `--min-turnover`.
Пересборка первого числа в 00:00 UTC; `--since` — тоже первое число месяца.
Стейблкоины и дополнительные исключения задаются в
`config/universe_exclusions.csv`; другой файл можно передать через
`--exclusions-file` в `candidates` и `build`.

Результат: `data/universe/core15.parquet` и `core15.meta.json`. В metadata
сохраняются параметры и происхождение входных данных. Нехватка символов
помечается по месяцам, отсутствующие кэши перечисляются отдельно.
Снимки, сделанные до T002a, нужно переснять для включения закрытых инструментов.
Вселенную старого формата нужно пересобрать (schema_version=2).

Пул включает `Trading` и `Closed` с одинаковыми фильтрами активов. Снимок
сохраняет также остальные статусы API. `listed_until_ms` берётся из
`deliveryTime`; при его отсутствии у Closed — из закрытия последней дневной
свечи, как оценка. У Trading конец не ограничен. Источник хранится в
`listed_until_source`, начало — в `listed_from_ms` (первая доступная свеча).
Все границы доступны в metadata `trading_periods`, а для выбранных символов
продублированы в колонках parquet.

**Ограничение:** API может не возвращать часть инструментов или их историю,
а классификация активов остаётся текущей. Объект `survivorship_bias` содержит
`delisted_included` (закрытые кандидаты с историей), `delisted_without_history`
и пояснение. Отдельно перечислены символы без истории и выбранные Closed;
`report` показывает их участие по месяцам. Устранение ошибки выжившего не гарантируется.

Для T003:

```python
from pathlib import Path
from trending_basket.universe.storage import load_universe

universe = load_universe(Path("data"), "core15")
symbols = universe.universe_at(1709251200000)  # 2024-03-01 00:00 UTC
can_trade = universe.is_tradeable_at("BTCUSDT", 1709251200000)
```

Возвращается последний состав не позже указанного времени, в порядке ранга.
До первой пересборки и в пустом месяце — пустой список.
`is_tradeable_at` проверяет полуинтервал `[первая свеча, listed_until_ms)`;
для неизвестного символа или отсутствующей истории возвращает False.
Это проверка границ листинга, а не гарантии наличия свечи или ликвидности
в любой момент внутри диапазона. T003 должен проверять её и между
месячными пересборками, закрывая позицию при делистинге и запрещая новые входы.
Известная сейчас будущая дата закрытия не влияет на более ранний отбор.

Основной период оценки T003/T005 начинается 2021-11-01 UTC (ADR-012),
после восстановления полной корзины в T002a. Январь–октябрь 2021 — дополнительная
история и прогрев. Начало выбрано до первых прогонов стратегии.

## Бэктест

Подготовка данных всех когда-либо выбранных символов:

```text
uv run tb universe members core15 --out data/universe/core15-members.txt
uv run tb data sync funding --symbols-file data/universe/core15-members.txt --since 2021-01-01
uv run tb data sync klines --symbols-file data/universe/core15-members.txt --interval 4h --since 2021-01-01
uv run tb backtest run experiments/bh_btc.toml
uv run tb backtest run experiments/ew_core15.toml
uv run tb backtest show reports/<run-directory>
uv run tb backtest compare reports/<btc-run> reports/<basket-run>
```

TOML фиксирует `run.period`, капитал, издержки и лимиты. Ручные `start/end` запрещены;
границы берутся из ADR-015, конечная дата включительно.
открытые позиции в конце переоцениваются, без дополнительной сделки закрытия.
Отчёт публикуется атомарно: исполнения, позиции, капитал и события в parquet,
метрики и манифест с хешами входов в JSON, сводка Markdown и два PNG-графика.
Одноимённый отчёт не перезаписывается. Два прогона с одинаковыми входами дают
одинаковые parquet/метрики; время создания хранится в манифесте через `Clock`.

Стратегия видит только закрытые свечи; исполнение — следующее открытие.
Стоп проверяется по high/low с правилом гэпа. Время касания неизвестно из OHLC:
обычный стоп датируется закрытием бара, гэп — открытием. Полный reduce-only выход
не блокируется входным минимумом; слишком маленькое сокращение увеличивается
до исполнимого размера или полного закрытия. Целевое количество округляется
к нулю; после комиссий и проскальзывания движок сокращает фактические позиции,
пока gross/net/symbol не окажутся в пределах лимитов + 1e−9. Каждая корректировка
и проверка после ребалансировки записываются в events.
Фандинг исторический, цена — точное открытие 4h или дневное открытие как fallback.
Покрытие использует интервалы соседних исторических меток каждой монеты:
смена расписания не считается пропуском. В отчёте — покрытие по символам и
список отсутствующих выплат с UTC-периодами; при недостатке истории покрытие
неизвестно. Пропуски требуют проверки соответствующих диапазонов через API.
В compare и report.md отдельно показаны ценовая доходность BTC без издержек
и валовая сумма уплаченного фандинга BTC. Инвариант, диагностика и ограничения — ADR-014.
Параметры инструментов текущие; маржа и ликвидации не моделируются (ADR-013).
Эталоны не являются проверкой прибыльности будущей трендовой стратегии.

## Трендовая корзина T004

Семь вариантов зарегистрированы до прогонов (ADR-015, `docs/experiments-log.md`).
Период `dev`: 2021-11-01–2024-06-30, `val`: 2024-07-01–2025-09-30,
`holdout`: с 2025-10-01 по последнюю закрытую UTC-дату; `full` с 2021-11-01.
Все файлы V1–V5, V1-10k, V2-10k и оба эталона настроены на dev.

```text
uv run tb backtest run experiments/V1.toml
uv run tb backtest run experiments/V2.toml
uv run tb backtest run experiments/V3.toml
uv run tb backtest run experiments/V4.toml
uv run tb backtest run experiments/V5.toml
uv run tb backtest run experiments/V1-10k.toml
uv run tb backtest run experiments/V2-10k.toml
```

Для стратегии `val` требует `--allow-val`; `holdout/full` — `--allow-holdout`
и интерактивное подтверждение. Допуск записывается до чтения данных в
`reports/period-access-log.jsonl`, включая неудавшиеся после допуска попытки.
В T004 защищённые периоды не запускаются. Эталоны освобождены от этого допуска;
BTC держит фиксированное количество (`limits.enabled=false`). Трендовая
стратегия не разрешает отключить контроль лимитов.

Три состояния каналов 20/55/100, дневной ATR Wilder 20, стоп 3 ATR,
риск 0.5% капитала на полный сигнал символа и полоса 25%. Варианты 4h используют
каналы по 120/330/600 барам и только закрытый дневной ATR. Исполненный стоп
обнуляет состояния; повторный вход требует строго более позднего пробоя.
R использует максимальный риск фактического номинала за жизненный цикл;
отчёт разделяет издержки лонгов/шортов и ранжирует закрытые позиции по R.

Реальные результаты всех зарегистрированных вариантов: [отчёт T004-dev](docs/reports/T004-dev.md).

## T004b: проверка гипотез на dev

`[execution] quantity_mode = "exchange"` по умолчанию сохраняет T004.
`exact` отменяет только округление количества и минимальные заявки; издержки,
фандинг и контроль фактической экспозиции сохраняются. Режим указан в заголовке
отчёта, метриках, манифесте и отдельной колонке compare. Exact — исследовательская
модель, а не биржевой режим исполнения. Метрики дополнены приближённой SE Sharpe
и средним номиналом непустой позиции на закрытиях баров.

```text
uv run tb backtest run experiments/V1x.toml
uv run tb backtest run experiments/V2x.toml
uv run tb backtest run experiments/V3x.toml
uv run tb backtest run experiments/V4x.toml
uv run tb backtest run experiments/H1.toml
uv run tb backtest run experiments/H2.toml
uv run tb backtest run experiments/H3.toml
uv run tb backtest run experiments/H3-1k.toml
uv run tb backtest run experiments/V2-1k.toml
```

Гипотезы независимы относительно V2x: H1 — выход по полному каналу;
H2 — разрешённая сторона альтов по закрытию BTC относительно SMA100, включая
выход при смене режима; H3 — top-5 по абсолютной 100-дневной доходности/ATR_frac,
с риском 1.5% на символ. У H2 отсутствие актуальных непрерывных дневных данных
BTC запрещает альтовые цели. H3 не закрывает позицию только из-за выпадения из
top-5, но запрещает её увеличение и разворот; старые позиции могут увеличить
общее число удерживаемых символов выше пяти. Равные оценки разрешаются по ID
символа. Значения по умолчанию выключают оба фильтра.

Регистрация, запрет дальнейшего перебора и критерии T005 — ADR-016 и журнал
экспериментов. T004b не открывает val/holdout/full для трендовой стратегии.

Факты и вердикты трёх гипотез: [отчёт T004b-dev](docs/reports/T004b-dev.md).

## T005: механический выбор и один holdout

Исходы зафиксированы до прогонов в ADR-017, критерии — ранее в ADR-016.
Конфигурации семи кандидатов и двух эталонов val: `experiments/val/`.

```text
uv run tb backtest run experiments/val/V1x.toml --allow-val
uv run tb research select --period val --candidates reports/V1x-STAMP --candidates reports/V2x-STAMP --candidates reports/V3x-STAMP --candidates reports/V4x-STAMP --candidates reports/H1-STAMP --candidates reports/H2-STAMP --candidates reports/H3-STAMP
uv run tb research holdout-verdict --candidate reports/SELECTED-HOLDOUT-STAMP --btc reports/bh_btc-HOLDOUT-STAMP
```

`select` требует ровно семь зарегистрированных кандидатов exact $10000 на val;
проверяет параметры и даты манифестов, сохраняет все метрики, причины исключения
и SHA-256 источников. Максимальный Sharpe при >=100 закрытых позиций и DD>=−20%,
точные равенства разрешаются по ID. `T005-selection.json` коммитится до holdout.
Отсутствие допустимых кандидатов запрещает holdout. `holdout-verdict` проверяет
выбранный ID, неизменность параметров, совпадение окна с BTC и три условия ADR-016.
Результаты по умолчанию пишутся в `docs/reports/T005-selection.json` и
`T005-holdout.json`; существующий файл не перезаписывается.

Любой повторный доступ стратегии к holdout/full блокируется журналом ещё до
чтения данных, включая повтор того же кандидата и неудавшуюся после допуска
попытку. Отдельный `--override-holdout-lock` оставляет предупреждение в журнале
и нарушает протокол T005; в T005 он не используется. Эталоны освобождены от
блокировки. Журнал действует в выбранном `reports_dir`: его удаление или смена
каталога обходит локальное ограничение и не является допустимым продолжением
T005. Одновременные допуски сериализуются файловой блокировкой.

При провале — остановка семейства и направление T007; при прохождении —
проверка exchange $1000 только на val, затем возможен Demo с малым риском T006.
Ни параметры, ни окно не пересматриваются по holdout.

[Отчёт T005](docs/reports/T005.md): выбран V1x, holdout пройден;
проверка exchange $1000 на val зафиксировала 936 пропусков минимальных заявок.

## T006a: Bybit Demo

Риск V1x зафиксирован на **0,65% на символ**, аварийная просадка — **20,094764%**
от сохранённого пика. Результаты dev/val и статус реальной проверки:
[отчёт T006a](docs/reports/T006a.md). Риск/критерии T006b — ADR-018.

В локальном `.env` задаются `TB_MODE=demo`, `TB_BYBIT_API_KEY`,
`TB_BYBIT_API_SECRET`, `TB_TELEGRAM_BOT_TOKEN`, `TB_TELEGRAM_CHAT_ID`,
`TB_ALLOCATED_CAPITAL_USD=1000` (выделенная сумма подтверждена владельцем).
Ключ создаётся в **Bybit Demo**, с правами торговли, без вывода. Привязка к IP
необязательна для Demo по решению владельца (ADR-019).
Нужен отдельный Unified Demo-счёт без чужих позиций/заявок. Капитал стратегии —
выделенная сумма + PnL её позиций − комиссии + фандинг из транзакций биржи.
Переоценка других монет кошелька не влияет на размеры заявок и просадку стратегии.
`totalEquity` используется только при проверке достаточности маржи; в cross margin
текущий и стрессовый MMR должны быть ниже 30% (ADR-020). Выделенную сумму во время
сегмента менять нельзя. Пустой `liqPrice` проверяется через minPrice/maxPrice,
а отсутствие необходимых данных по-прежнему приводит к защитному закрытию.
Demo и Testnet — разные среды. Приватный адрес строго `https://api-demo.bybit.com`;
`TB_BYBIT_DEMO_REST_URL` в `.env.example`. Секреты не коммитятся и не печатаются.

```text
uv run tb demo check
uv run tb run --mode demo --once --dry-run
uv run tb run --mode demo --once
```

`demo check` обновляет публичный кэш и проверяет авторизацию, часы, счёт,
права ключа, чужие позиции/заявки, свежесть свечей и инструментов, Telegram.
Изменяющих биржевых запросов нет. `dry-run` печатает цели, дельты и стопы,
не продвигает состояние дня и не отправляет уведомлений. При `once` используется
последнее дневное закрытие, доступное после 00:03 UTC; опоздание помечается.
Уже выполненный день повторно не торгуется, но позиции/стопы проверяются.
После завершения `once` автоматический надзор прекращается, биржевые стопы остаются.

Для последующей T006b предусмотрен `uv run tb run --mode demo --loop`: процесс
ожидает ежедневные решения и между ними сверяет счёт/защиту каждые 10 секунд.
Сам по себе запуск на сервере или автоматическое возобновление здесь не настроены.
Флаг аварийной остановки снимается только `uv run tb run resume` с показом причины,
подтверждением в консоли и успешной сверкой. Пик капитала не сбрасывается.
Удалять checkpoint или принимать чужие позиции за свои нельзя.
Пошаговый самостоятельный перезапуск: [инструкция](docs/DEMO-RUNBOOK.md).
Уведомления Telegram выводятся на русском языке.

Журналы и состояние: `data/live/demo/` (`decisions`, `orders`, `fills`, `positions`,
`equity`, `events`, `funding`, `shadow` в JSONL и `state.json`). Shadow ведёт
собственную постоянную книгу через тот же `SimExecutor`; защитные закрытия
исполнителя не закрывают его позиции и не сбрасывают сигналы стратегии. Вторая копия процесса блокируется.
Незавершённые заявки восстанавливаются по сохранённым ID; после простоя более семи
дней автоматическая сверка не может подтвердить полноту Demo-истории и отказывает.

Повторять расчёт риска для запуска Demo не нужно: результат уже закоммичен.
Команда воспроизведения на **новый** файл (только dev/val, не holdout):

```text
uv run tb research risk-level --dev reports/V1x-DEV-STAMP --val reports/V1x-VAL-STAMP --allow-val --output reports/risk-level-reproduction.json
```
