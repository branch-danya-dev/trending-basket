# trending-basket — инструкции для агента

## Что это за проект

Личный фоновый торговый бот для линейных USDT-перпетуалов Bybit. Горизонт решений — 4 часа и 1 день, позиции держатся от дней до недель.

Модули по порядку появления:

1. **Трендовая корзина** — основная стратегия MVP.
2. **Funding carry** — рыночно-нейтральный модуль, позже.
3. **ML** — только вспомогательная роль (прогноз волатильности для размера позиций, затем meta-labeling) и только после того, как база без ML прошла проверку на истории.

Статус: MVP в разработке. Бот не торгует реальными деньгами. Режим `live` запрещён кодом до отдельной задачи в `docs/ROADMAP.md`.

## Уроки прошлого проекта (scalp-bot), обязательные здесь

- **Сначала данные и бэктест, потом исполнение.** Ни одно торговое правило не пишется и не включается без проверки на истории с учётом издержек.
- **Одна задача — одна ветка — один PR.** Не добавлять функции, режимы, профили, «гейты», параметры и документы, которых нет в текущей задаче.
- **Готовые изменения отправляются на GitHub.** После проверок закоммить изменения и отправь рабочую ветку в `origin` без дополнительного подтверждения. Не оставляй результат только локально. Это не разрешает автоматический merge или force push.
- **Каждое число стратегии имеет источник.** Параметр появляется либо из исследования (со ссылкой на отчёт), либо фиксируется в `docs/DECISIONS.md` с обоснованием. Формулировка «policy choice» без обоснования недопустима.
- **Издержки учитываются всегда:** комиссии, фандинг, проскальзывание.
- **Сложность — это стоимость.** Прежде чем добавить модуль, класс или зависимость, проверить, нельзя ли решить задачу проще.

## Технические правила

**Окружение и запуск**

- Python 3.12, менеджер окружения `uv`, src-layout, пакет `trending_basket`, CLI-команда `tb`.
- Кросс-платформенность: разработка на Windows, позже сервер на Linux. Точки входа только через CLI `tb`. Скрипты PowerShell или bash не могут быть единственным способом запуска.

**Время**

- Код в `domain/`, `strategies/`, `portfolio/`, `backtest/` не обращается к системным часам: `time.time`, `time.monotonic`, `datetime.now`, `datetime.utcnow`, `date.today`. Время приходит только через переданный `Clock` или явный timestamp. Это проверяет тест `tests/test_no_system_clock.py`.
- Все временные метки — UTC: либо `int` миллисекунд epoch, либо timezone-aware `datetime`. Naive datetime запрещён (правило ruff `DTZ`).

**Деньги, единицы и конфигурация**

- На границе с биржей цена и количество заявки — `Decimal` с нормализацией по параметрам инструмента. Внутри исследований и бэктеста допустим `float64`.
- Единицы указываются в именах:
  - `_bps` — базисные пункты;
  - `_frac` — доля (0.01 = 1%);
  - `_usd` — доллары;
  - `_ms` — миллисекунды.
- Конфигурация — `pydantic-settings` с префиксом `TB_`. Неизвестная переменная `TB_*` — ошибка старта.

**Секреты и данные**

- Секреты только в переменных окружения или `.env`, который в `.gitignore`.
- API-ключи создаются с правом торговли, без права вывода средств. Для Demo привязка к IP необязательна по решению владельца (ADR-019); для будущего live требование привязки сохраняется.
- Каталоги `data/` и `reports/` не коммитятся.

**Тесты и зависимости**

- В тестах сеть запрещена. Внешние API тестируются на записанных фикстурах в `tests/fixtures/`.
- Новая зависимость добавляется только в той задаче, где она нужна, с обоснованием в PR.

**Язык**

- Код, идентификаторы, комментарии в коде и сообщения коммитов — английский.
- Документация в `docs/` — русский.

## Проверки перед завершением любой задачи

```
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest
```

Все четыре команды должны проходить. CI на GitHub Actions выполняет их на Ubuntu и Windows.

## Отчёт по задаче (описание PR)

1. **Что сделано.**
2. **Что сознательно не сделано.**
3. **Допущения.**
4. **Как проверить:** команды и ожидаемый результат.
5. **Новые зависимости**, если есть, с обоснованием.

Изменения поведения, которые не требовались задачей, в PR не входят.
