# Архитектура

## Поток данных

```
data → backtest/research → strategies (целевые веса) → portfolio (риск, размер)
     → execution (целевые позиции → разница с фактическими → заявки) → reporting
```

## Принципы

- **Один путь кода** для бэктеста, Demo и live: различаются только источник данных и исполнитель.
- **Время** только через `Clock`.
- **Издержки** (комиссии, фандинг, проскальзывание) учитываются всегда.
- **Исполнение идемпотентно:** после перезапуска бот сверяет фактические позиции с целевыми и приводит их в соответствие.
- **Стопы на стороне биржи.**

## Исполнение T006a

`execution/bybit_private.py` — подпись, Demo-only транспорт и восстановление
заявок по ID. `planning.py` — Decimal-граница инструмента; `live_executor.py` —
сверка фактических позиций, исполнение, биржевые стопы и исправление фактических
экспозиций через общие лимиты. `cycle.py` строит контекст того же `TrendBasket`
через `MarketView`; `cli.py` организует preflight/once/loop/resume.

`journal.py` сохраняет checkpoint до сетевого побочного эффекта. В именованных
прогонах `ledger.py` объединяет каналы в один journal.jsonl с цепочкой хешей
и полной последовательностью; state.json восстанавливается из fsync-checkpoint.
OS-блокировка запрещает одновременное управление одним состоянием. Решение,
состояние стратегии после него и shadow сохраняются вместе; продолжение использует
этот checkpoint. Реальные fills дедуплицируются по execId. У стратегии нет доступа
к приватному клиенту, а клиент исполнения не может перейти на mainnet/live.

Публичные данные используют существующий кэш; отдельная `demo-core15` сохраняет
месячные составы исполнения. Исторические конфигурации/отчёты T005 не изменяются.
Dry-run работает с копией checkpoint и запретом POST на уровне транспорта.

`capital.py` ведёт выделенную кривую: собственные fills/комиссии, историческое
владение для фандинга из transaction-log и unrealisedPnl биржевых позиций.
Повторы исполнений и транзакций не удваивают суммы. `margin.py` отдельно
проверяет границу ликвидации и совокупный стресс до стопов по ADR-020.
Оценка залога кошелька не используется как капитал стратегии.
Shadow сохраняет собственную книгу и состояния; защитные выходы исполнителя
сохраняют сигналы и намерение восстановить позицию на следующем решении.

`runs.py` управляет явным стартом/закрытием и неизменяемыми параметрами прогона.
`continuity.py` восстанавливает четыре потока истории биржи, дедуплицирует записи,
ведёт heartbeat/простой и сетевые повторы. `replay.py` независимо пересчитывает
стратегию по исходным контекстам и свечам, капитал — по исполнениям/фандингу,
восстанавливает дневные точки. Защитный выход не становится стоп-событием стратегии.
`service.py` формирует подтверждаемую задачу Планировщика Windows.
