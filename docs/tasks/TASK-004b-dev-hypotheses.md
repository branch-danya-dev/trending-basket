# T004b — точная модель количества и три гипотезы на dev

## Контекст

Прочитай `CLAUDE.md`, `docs/DECISIONS.md`, `docs/reports/T004-dev.md`. T004 смержен.

На периоде разработки все варианты дали доходность около нуля при Sharpe от −0,08 до 0,23. За 2,7 года стандартная ошибка Sharpe около 0,6, так что результат статистически неотличим от нуля. Выбирать сейчас «лучший» вариант на валидации значило бы выбирать шум.

Из отчёта T004 видны три вещи, которые нужно понять до T005:

1. **Прогоны на $1000 искажены минимальными заявками.** 1168–17 897 пропусков против 29–101 на $10 000. Логику стратегии надо оценивать без округления, а реализуемость на реальном капитале — отдельно.
2. **Выигрышные позиции в среднем всего 1,0–1,3R.** Трендовая система живёт крупными выигрышами. Гипотеза: выход по каналу `L/2` обрывает тренды рано.
3. **Потери сконцентрированы в общих откатах рынка** (2022, конец декабря 2023 — начало января 2024) и в лонгах альтов при падающем BTC.

Задача работает только на `dev`. Валидация и отложенный период не трогаются.

## 1. Первый коммит — регистрация до любых прогонов

В `docs/experiments-log.md` и `docs/DECISIONS.md` записываются три вещи: гипотезы, запрет на дальнейшие варианты и критерии T005.

### Гипотезы

Каждая — одно изменение относительно базы `B = V2x` (1d, long_short, режим `exact`). База выбрана как общий случай: long_only — частный случай long_short. Выбор базы не основан на результате V2.

| ID | Гипотеза | Изменение | Что считается подтверждением на dev |
|---|---|---|---|
| H1 | Выход по короткому каналу обрывает тренды | `exit_ratio = 1.0` вместо 0.5 | Средний выигрыш в R и Sharpe выше, чем у B |
| H2 | Лонги альтов против падающего BTC и шорты альтов против растущего BTC — основной источник потерь | Лонг по символу, кроме BTC, разрешён только при закрытии BTC выше его 100-дневной SMA; шорт — только ниже. BTC торгуется без фильтра | Меньше просадка и выше Sharpe, чем у B |
| H3 | Концентрация на сильнейших трендах лучше, чем все пробои сразу | Новые входы только в 5 символов с наибольшим `|доходность за 100 дней| / ATR_frac` среди символов с ненулевым сигналом. Уже открытые позиции ведутся до выхода. Риск на символ `0.5% × 15 / 5 = 1.5%`, чтобы общий риск-бюджет остался сопоставимым | Sharpe выше, чем у B; в режиме `exchange` на $1000 пропусков заметно меньше |

### Запрет на дальнейшие варианты

Значения 1.0, 100 дней и 5 символов — стандартные, не подобранные на наших данных. После прогонов они **не** перебираются: никаких SMA 50/150 или top-3/top-8. Если гипотеза не подтвердилась, она отклоняется, а не донастраивается.

### Критерии T005, фиксируемые сейчас

- **Кандидаты:** V1x, V2x, V3x, V4x, H1, H2, H3 — все в режиме `exact`.
- **Выбор на `val`:** наибольший Sharpe при условии не меньше 100 закрытых позиций за период и максимальной просадки не хуже −20%.
- **Проверка на `holdout`**, один прогон выбранного кандидата. Проходит, если одновременно:
  - Sharpe > 0;
  - максимальная просадка не хуже −25%;
  - результат лучше `buy_and_hold_btc`, скорректированного на ту же волатильность: доходность BTC, умноженная на отношение волатильности кандидата к волатильности BTC.
- **Если holdout не пройден:** стратегия этого семейства не переходит к исполнению. Параметры по результатам holdout не меняются.

## 2. Режим количества в движке

Новое поле TOML `[execution] quantity_mode = "exchange" | "exact"`.

- **`exchange`** — текущее поведение: округление по `qtyStep`, пропуск ниже минимумов.
- **`exact`** — количество дробное без округления и минимумов. Остальное без изменений: комиссии, проскальзывание, фандинг, лимиты на фактических позициях.

Режим записывается в `manifest.json`, `metrics.json` и в заголовок `report.md`. `compare` показывает режим в отдельной колонке.

Тесты:

- в `exact` пропусков по минимуму нет, а количество равно `номинал / цена`;
- в `exchange` поведение T003/T004 не изменилось (регрессия на сохранённом эталонном прогоне);
- тождество капитала выполняется в обоих режимах.

## 3. Реализация гипотез

Параметры стратегии в `trend_basket.py`:

| Параметр | По умолчанию | Для гипотезы |
|---|---|---|
| `exit_ratio` | 0.5 | H1: 1.0 |
| `btc_regime_filter` | `off` | H2: `sma` |
| `btc_regime_sma_days` | 100 | H2 |
| `concentration_top_k` | `None` | H3: 5 |
| `concentration_rank_days` | 100 | H3 |

Значения по умолчанию сохраняют поведение T004 байт в байт. Это проверяется регрессионным тестом на V1.

- **H2.** Используются только дневные закрытия BTC до момента решения. Если данных BTC на дату нет, фильтр запрещает новые входы в альты, а не пропускает их.
- **H3.** Ранжирование на каждом решении по данным до `t`. Символ, выпавший из top-K, новых входов и увеличений не получает, существующая позиция ведётся по своим правилам.

Тесты на синтетике:

- H1 меняет только правило выхода подсистем;
- H2 блокирует лонг альта при BTC ниже SMA и разрешает при выше; зеркально для шорта; BTC не фильтруется; отсутствие данных BTC блокирует;
- H3 открывает не больше K новых позиций, ранжирование без заглядывания вперёд, существующие позиции не закрываются принудительно.

## 5. Отчёт `docs/reports/T004b-dev.md`

1. Таблица метрик всех прогонов, включая колонку режима.
2. Для каждого прогона — Sharpe и его стандартная ошибка `sqrt((1 + SR²/2) / T)`, где T — длина периода в годах.
3. Для H1–H3 — разница с B по Sharpe, просадке, среднему выигрышу и проигрышу в R, числу позиций, экспозиции; разбивка по годам.
4. Корреляция дневных доходностей между всеми вариантами и с BTC.
5. Сравнение `exact` и `exchange` для V1–V4: что именно меняет округление.
6. H3-1k против V2-1k: пропуски по минимуму, средний размер позиции, доходность.
7. Для каждой гипотезы — вердикт по критерию из таблицы в пункте 1: «подтверждена на dev» или «не подтверждена». Без выбора итогового варианта: выбор делается в T005 по зафиксированному критерию.
