# T002 — вселенная символов на момент времени

## Контекст

Прочитай `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, `docs/DECISIONS.md`. T001 выполнен: есть клиент публичного API, кэш свечей 1d/4h, фандинга и снимков инструментов, работа проверена на реальном API.

Задача: для любой даты в прошлом определить, какими символами торговала бы стратегия, используя **только данные, доступные до этой даты**. Результат — таблица вселенной по месяцам, которую T003 (бэктест) использует как вход.

## Известное ограничение: ошибка выжившего

По описаниям `GET /v5/market/instruments-info` для linear, скорее всего, возвращаются только торгующиеся сейчас символы. Проверь это на реальном снимке и запиши результат в отчёт.

Если делистингованных символов в ответе нет, пул кандидатов строится из сегодняшнего списка. Монеты, которые торговались в прошлом и были удалены, в историю не попадут. Результаты бэктеста из-за этого будут завышены. Эта задача:

- не пытается восстановить удалённые символы;
- обязана явно пометить ограничение в метаданных вселенной и в отчёте;
- снижает влияние ограничения отбором по ликвидности: топ по обороту в основном состоит из крупных монет, которые реже удаляются.

Отдельно: ежедневные снимки инструментов с этого момента (`tb data sync instruments`) позволят в будущем строить вселенную без этой ошибки. Их автоматизация — задача развёртывания, здесь не делается.

## Что сделать

### 1. Пул кандидатов — `universe/candidates.py`

Из последнего снимка инструментов выбираются символы с `contractType = LinearPerpetual`, `quoteCoin = USDT`, `status = Trading`.

Затем исключаются:

- стейблкоины как базовый актив (список в файле исключений);
- инструменты с некриптовым базовым активом: акции, индексы, сырьё, токенизированные акции. Изучи реальный снимок, найди поля или признаки, по которым их можно отличить, и предложи правило. Если надёжного признака нет — явный список;
- символы из файла исключений.

Файл исключений — `config/universe_exclusions.csv` с колонками `symbol_or_base`, `reason`. Он коммитится в репозиторий.

Команда `tb universe candidates --out data/universe/candidates.txt` пишет список кандидатов по одному символу в строке. Этот файл подаётся в `tb data sync klines --symbols-file`.

### 2. Отбор на дату — `universe/selection.py`

Вселенная пересобирается раз в месяц. Дата пересборки — первый день месяца 00:00 UTC. Она использует только свечи, **закрытые до этой даты**.

Символ допускается на дату `d`, если:

| Условие | Параметр | Значение по умолчанию |
|---|---|---|
| История свечей 1d до `d` не короче N дней | `min_history_days` | 120 |
| Медианный дневной оборот за последние W дней до `d` не ниже порога | `turnover_window_days`, `min_median_turnover_usd` | 30; 10 000 000 |
| В окне W нет пропусков свечей | — | — |

Допущенные символы ранжируются по медианному обороту (при равенстве — по имени символа), берутся первые `top_n` (по умолчанию 15).

Если допущенных меньше `top_n`, берутся все, а месяц помечается в отчёте. Так, скорее всего, будет в начале 2021 года.

Значения по умолчанию — это решения, а не результат оптимизации. Запиши их в `docs/DECISIONS.md` с обоснованием:

- 120 дней — не короче самого длинного горизонта будущих трендовых сигналов с запасом;
- медиана вместо среднего — устойчивость к всплескам;
- ежемесячная пересборка — меньше лишней смены состава.

### 3. Хранение результата

```
{data_dir}/universe/{name}.parquet
{data_dir}/universe/{name}.meta.json
```

Колонки parquet: `rebalance_time_ms` (int64), `symbol`, `rank` (int), `median_turnover_usd`, `history_days`.

`meta.json` содержит:

- все параметры отбора;
- время создания — через `Clock`;
- git commit, если доступен;
- имя снимка инструментов;
- по каждому входному файлу свечей — число строк и последнее время;
- флаг `survivorship_bias: true` с пояснением.

Запись атомарная, как в кэше T001.

### 4. CLI

| Команда | Что делает |
|---|---|
| `tb universe candidates --out PATH` | Пул кандидатов из последнего снимка инструментов |
| `tb universe build --name core15 --since 2021-01-01 [--top 15] [--min-history-days 120] [--turnover-window 30] [--min-turnover 10000000]` | Строит вселенную по месяцам от `--since` до текущего месяца включительно |
| `tb universe report core15` | Таблица по месяцам: число символов, вошедшие и вышедшие символы, минимальный и медианный оборот в составе, помеченные месяцы |
| `tb universe show core15 --at 2024-03-01` | Состав на конкретную дату пересборки |

Символы без кэша свечей в отчёте `build` перечисляются отдельно: им нужен `sync`. `build` при этом не падает.

### 5. Функция для T003

`universe_at(time_ms) -> list[str]` — состав, действующий в момент `time_ms`, то есть с последней пересборки не позже `time_ms`. Бэктест будет вызывать её на каждой ребалансировке.

## Тесты (без сети, на синтетических данных)

- **Заглядывание вперёд:**
  - вселенная на дату `d` не меняется, если изменить или дописать свечи с временем `≥ d`;
  - свеча, открывшаяся в последний день до `d`, но закрывающаяся ровно в `d`, учитывается;
  - свеча, открывшаяся в `d`, — нет.
- **Фильтры:** история короче N дней → не допущен; пропуск свечи в окне W → не допущен; оборот ниже порога → не допущен.
- **Ранжирование:** детерминированно, при равном обороте — по имени.
- **Нехватка символов:** допущенных меньше `top_n` → все допущенные, месяц помечен.
- **Кандидаты:** фильтрация по `contractType`, `quoteCoin`, `status`; исключения из файла; стейблкоины.
- **`universe_at`:** граничные случаи — ровно в момент пересборки, до первой пересборки (пустой список или ошибка — выбрать и задокументировать).
- **Хранение:** атомарная запись; повторный `build` на тех же данных даёт идентичный parquet; `meta.json` содержит все параметры.
- **CLI** на временном `data_dir`.

## Вне рамок задачи

Стратегии, бэктест, восстановление делистингованных символов, автоматизация ежедневных снимков, данные спота.

## Критерии готовности

1. Все проверки из `CLAUDE.md` зелёные; CI зелёный на Ubuntu и Windows.
2. Ручная проверка владельцем на Windows, реальные данные:
   ```
   uv run tb data sync instruments
   uv run tb universe candidates --out data/universe/candidates.txt
   uv run tb data sync klines --symbols-file data/universe/candidates.txt --interval 1d --since 2021-01-01
   uv run tb universe build --name core15 --since 2021-01-01
   uv run tb universe report core15
   uv run tb universe show core15 --at 2024-03-01
   ```
3. В отчёте по задаче:
   - число кандидатов;
   - сколько из них имеют историю с 2021 года;
   - подтверждено ли, что снимок инструментов не содержит делистингованных символов;
   - какое правило исключения некриптовых инструментов выбрано и почему;
   - какие месяцы помечены из-за нехватки символов;
   - состав на 2021-06-01 и на последнюю дату пересборки.
4. `docs/DECISIONS.md` дополнен решениями по параметрам вселенной и по ошибке выжившего. В `docs/ROADMAP.md` T002 отмечен выполненным после мержа.
