# T001 — данные: публичный REST-клиент Bybit и локальный кэш

## Контекст

Прочитай `CLAUDE.md`, `docs/ARCHITECTURE.md` и `docs/ROADMAP.md`. T000 выполнен.

Эта задача даёт проекту историю рынка: свечи 4h и 1d, историю фандинга и параметры инструментов линейных USDT-перпетуалов Bybit. Всё сохраняется в локальный кэш parquet с идемпотентной докачкой и проверкой пропусков. Используются только публичные эндпоинты API v5, без ключей.

Детали API ниже приведены по памяти. **Перед реализацией сверь каждое поле, лимит и порядок сортировки с официальной документацией Bybit v5.** Расхождения опиши в отчёте.

## Эндпоинты

| Назначение | Эндпоинт | Что важно |
|---|---|---|
| Время сервера | `GET /v5/market/time` | Нужно, чтобы отбросить незакрытую свечу |
| Свечи | `GET /v5/market/kline` | `category=linear`; `interval` `240` или `D`; `start`/`end` в мс; `limit` до 1000. Список приходит от новых к старым. Элемент: `[startTime, open, high, low, close, volume, turnover]` строками. Последняя свеча может быть незакрытой |
| История фандинга | `GET /v5/market/funding/history` | `category=linear`; `limit` до 200; пагинация назад через `endTime`. Уточни по документации, как ведут себя запросы только со `startTime` |
| Инструменты | `GET /v5/market/instruments-info` | `category=linear`; пагинация через `cursor`. Нужны `symbol`, `contractType`, `status`, `baseCoin`, `quoteCoin`, `launchTime`, `deliveryTime`, `fundingInterval`, `priceFilter.tickSize`, `lotSizeFilter` (`minOrderQty`, `maxOrderQty`, `qtyStep`, `minNotionalValue`) |

Базовый URL — из настроек, по умолчанию `https://api.bybit.com`.

## Что сделать

### 1. `data/bybit_client.py` — клиент публичного API

Класс `BybitPublicClient`. В конструктор передаются настроенный `httpx.Client` (в тестах — с `MockTransport`), политика повторов, ограничитель частоты и функция `sleep`.

**Методы:**

- `server_time_ms() -> int`
- `fetch_klines(symbol, interval, start_ms, end_ms) -> list[Candle]` — одна страница;
- `iter_klines(symbol, interval, start_ms, end_ms)` — пагинация по всему диапазону без дублей и пропусков на стыках страниц;
- `fetch_funding_history(symbol, start_ms, end_ms) -> list[FundingRate]` — со всей пагинацией;
- `fetch_instruments() -> list[InstrumentInfo]` — со всей пагинацией по `cursor`.

**Поведение:**

- Результаты всегда отсортированы по возрастанию времени.
- Незакрытая свеча (`open_time_ms + duration_ms > server_time_ms`) отбрасывается.
- `InstrumentInfo` — новый frozen dataclass в `domain/types.py`. Цена шага и лоты хранятся как `Decimal`, потому что это граница с биржей (правило из `CLAUDE.md`).

**Ошибки и повторы.** Повторяются только GET-запросы, при:

- таймауте и сетевой ошибке;
- HTTP 5xx и HTTP 429;
- `retCode = 10006` (превышен лимит частоты);
- других кодах лимита частоты, найденных в документации.

Экспоненциальная пауза с джиттером, максимум попыток из настроек. Любой другой ненулевой `retCode` сразу поднимает `BybitAPIError(ret_code, ret_msg, endpoint, params)`. Исчерпание попыток — тоже `BybitAPIError` с последней причиной.

**Ограничитель частоты.** Минимальный интервал между запросами из настроек. Время и `sleep` внедряются, поэтому тесты не ждут реально.

### 2. `data/cache.py` — локальный кэш parquet

**Раскладка:**

```
{data_dir}/bybit/linear/klines/{interval}/{SYMBOL}.parquet
{data_dir}/bybit/linear/funding/{SYMBOL}.parquet
{data_dir}/bybit/linear/instruments/{YYYY-MM-DD}.parquet
```

Снимок инструментов датируется днём UTC, в который он получен. Старые снимки не перезаписываются: они понадобятся в T002 для отбора символов на момент времени.

**Колонки:**

- свечи — `open_time_ms` (int64), `open`, `high`, `low`, `close`, `volume`, `turnover` (float64);
- фандинг — `funding_time_ms` (int64), `rate_frac` (float64);
- инструменты — все поля `InstrumentInfo`, `Decimal`-поля строками.

**Синхронизация `sync_klines(symbol, interval, since_ms)`:**

1. Прочитать существующий файл.
2. Докачать от последней сохранённой свечи (или от `since_ms`, если файла нет) до последней закрытой.
3. Объединить, удалить дубли по времени, отсортировать, провалидировать.
4. Записать атомарно: сначала во временный файл рядом, затем `os.replace`. Должно работать на Windows.

Если `since_ms` раньше первой сохранённой свечи — докачать и начало тоже. Для фандинга — та же логика, `sync_funding(symbol, since_ms)`.

**Идемпотентность.** Повторный запуск без новых закрытых свечей не меняет содержимое файла и сообщает «0 новых строк».

**Валидация.** Векторизованная проверка по тем же правилам, что у `Candle` в `domain/types.py`:

- цены > 0;
- `high`/`low` согласованы с `open`/`close`;
- объём ≥ 0;
- время выровнено по интервалу;
- время строго возрастает.

Тест проверяет, что векторизованная проверка и `Candle.__post_init__` отвергают одни и те же строки. Строки с нарушениями не записываются, а попадают в отчёт синхронизации.

**Пропуски.** `find_gaps(df, interval)` возвращает диапазоны отсутствующих свечей между первой и последней. Пропуски не заполняются искусственно, только сообщаются.

### 4. CLI

| Команда | Что делает |
|---|---|
| `tb data sync klines --symbols BTCUSDT,ETHUSDT --interval 1d --since 2021-01-01` | Синхронизирует свечи; `--interval` принимает `4h` и `1d` |
| `tb data sync funding --symbols ... --since ...` | Синхронизирует историю фандинга |
| `tb data sync instruments` | Сохраняет снимок инструментов за сегодня (UTC) |
| `tb data check [--symbols ...] [--interval ...]` | По кэшу: диапазон дат, число строк, пропуски, ошибки валидации; код выхода 1 при пропусках или ошибках |
| `tb data show SYMBOL --interval 1d --tail 5` | Последние строки из кэша |

Правила CLI:

- Символы передаются явно или через `--symbols-file` (по одному в строке). Списка по умолчанию нет: отбор вселенной — задача T002.
- Итоговая сводка `sync`: по каждому символу — добавлено строк, диапазон, пропуски, отвергнутые строки, ошибки.
- Ошибка по одному символу не прерывает остальные, но итоговый код выхода 1.
- Клиент создаётся через фабрику, которую тесты подменяют клиентом с `MockTransport`.

### 6. Тесты (все без сети)

- **Разбор свечей:** обратный порядок → возрастающий; отбрасывание незакрытой свечи при заданном времени сервера.
- **Пагинация свечей:** покрывает диапазон без дублей и пропусков на стыках страниц; корректно останавливается.
- **Пагинация фандинга назад** и **пагинация инструментов по `cursor`.**
- **Повторы:**
  - 429 → успех;
  - `retCode 10006` → успех;
  - неповторяемый `retCode` → немедленная ошибка;
  - исчерпание попыток → ошибка;
  - паузы растут (проверка через внедрённый `sleep`).
- **Ограничитель частоты** на внедрённых времени и `sleep`.
- **Кэш:**
  - первая синхронизация;
  - повторная — «0 новых строк» и неизменный файл (сравнение хеша содержимого);
  - докачка хвоста;
  - докачка начала;
  - атомарная запись не оставляет временных файлов;
  - отвергнутые строки не записываются.
- **Пропуски:** `find_gaps` на синтетических данных с одной и несколькими пропущенными свечами.
- **Согласованность:** векторизованная валидация и `Candle` отвергают одни и те же строки.
- **CLI:** `sync klines`, `check`, `show` на клиенте с `MockTransport` и временном `data_dir`.
