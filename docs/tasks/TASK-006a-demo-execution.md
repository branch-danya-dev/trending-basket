# T006a — исполнение на Bybit Demo

## Контекст

Прочитай `CLAUDE.md`, `docs/DECISIONS.md` (ADR-015–ADR-017), `docs/reports/T005.md`. T005 смержен:

- кандидат V1x — 1d, long_only, параметры T004 без изменений;
- отложенный период пройден по заранее записанным условиям;
- действует ветка «подготовка Demo с малым риском, проход не доказывает преимущество».

Задача — слой исполнения, который выполняет решения **того же кода стратегии и портфельных лимитов**, что и бэктест, на демо-счёте Bybit. Биржевые стопы, сверка с биржей, уведомления, аварийная остановка.

Двухнедельный прогон и его анализ — отдельная задача T006b. Здесь — реализация, предстартовые проверки и один реальный цикл.

## Запреты

- Параметры стратегии, кандидат и лимиты не меняются.
- Режим `live` и адреса основной сети остаются запрещены кодом.
- Отложенный период не используется ни для каких решений этой задачи.

## 0. Первый коммит — решения до реализации

Записать в `docs/DECISIONS.md`.

### Уровень риска

Скрипт `tb research risk-level` подбирает `risk_per_symbol_frac` для V1x **только по `dev` и `val`** (exact, $10 000, склеенная дневная доходность двух периодов) по правилу:

- целевая годовая волатильность портфеля 12%;
- шаг округления вниз 0,05 п.п.;
- потолок 1,0% на символ;
- лимиты gross/net/symbol 2/1,5/0,5 не меняются.

Скрипт запускает прогоны V1x с найденным риском на `dev` и `val` и записывает `docs/reports/T006-risk-level.json`: найденное значение, волатильность, Sharpe, максимальная просадка на каждом периоде. Масштаб риска почти не меняет Sharpe, но пропорционально увеличивает просадку. Её нужно видеть до Demo.

### Уровень риска на $1000

Тот же V1x с найденным риском на `val` в режиме `exchange` с $1000: пропуски по минимуму и средний размер позиции. Число записывается рядом.

### Критерии аварийной остановки

Действуют в Demo и позже в live.

| Условие | Действие |
|---|---|
| Просадка капитала от пика больше `max(1,5 × худшая просадка V1x на dev+val при выбранном риске, 15%)` | Остановка, разбор |
| Позиция без подтверждённого биржевого стопа дольше 60 секунд после исполнения | Закрыть позицию по рынку, остановка |
| Расхождение позиций бота и биржи при сверке | Остановка без торговых действий |
| Чужие позиции или заявки на счёте | Отказ стартовать |
| Цена ликвидации ближе к входу, чем 1,5 × расстояние до стопа | Уменьшить позицию до соблюдения, уведомить |
| Серия ошибок API (5 подряд) или время биржи не синхронизировано | Остановка новых действий, стопы на бирже не трогаются |

### Критерии T006b (двухнедельный Demo)

Записываются сейчас.

- **Технические:**
  - 14 календарных дней без ручных вмешательств в торговлю;
  - у каждой позиции был биржевой стоп;
  - все ежедневные циклы выполнены или помечены как пропущенные с причиной;
  - сверка без расхождений.
- **Исполнение:** медианное проскальзывание входов и выходов относительно цены решения не хуже 3× от заложенного в бэктесте. Иначе модель издержек пересматривается до live.
- **Результат за 14 дней не оценивается:** это слишком короткий срок.

## 1. Приватный клиент `execution/bybit_private.py`

REST-клиент с подписью запросов API v5 (HMAC-SHA256, `recv_window`, время запроса по синхронизированным часам биржи). Базовый URL Demo берётся из настроек.

Перед реализацией сверь с официальной документацией Bybit v5:

- адрес Demo-окружения;
- какие эндпоинты Demo поддерживает;
- формат подписи;
- коды ошибок.

Расхождения опиши в отчёте. В scalp-bot есть рабочий опыт с Demo: можно посмотреть, как там решены подпись, сверка и предстартовая проверка, но код пишется под интерфейсы этого проекта и с тестами (ADR-005).

**Нужные операции:**

- баланс счёта и тип счёта;
- список позиций;
- открытые заявки;
- история исполнений (реальные цены и комиссии);
- создание, изменение и отмена заявки;
- установка стопа на позицию;
- установка плеча по символу;
- информация о ключе API (права), если эндпоинт доступен.

**Идемпотентность.** Каждая заявка получает детерминированный `orderLinkId` из даты решения, символа и порядкового номера. При таймауте ответа сначала запрашивается состояние заявки по `orderLinkId`, и только если её нет — повторная отправка.

**Защита.** Если `TB_MODE` не `demo` или базовый URL не Demo, клиент не создаётся. Тест это проверяет.

## 2. Исполнитель `execution/live_executor.py`

Тот же интерфейс, что у `SimExecutor`: целевые позиции после `portfolio/limits.py` → заявки.

**Разница с биржей.** Разница считается между целями и **фактическими позициями с биржи**, а не с внутренним состоянием.

**Размер заявки.** Округление в режиме `exchange` по свежему снимку инструментов с правилами T003: к нулю, сокращения — в сторону меньшего риска.

**Тип заявок.** Рыночные, как в бэктесте. Сокращения и закрытия — с `reduceOnly`.

**Стоп на бирже.** После каждого изменения позиции стоп выставляется на позицию: срабатывание по цене последней сделки, на весь размер. Затем подтверждается чтением позиции. Если за 60 секунд стоп не подтверждён — закрыть позицию по рынку и остановиться. Трейлинг-стоп обновляется на каждом ежедневном решении и никогда не ослабляется: это проверяет и код, и тест.

**Плечо.** Плечо по символу выставляется умеренным (по умолчанию 3x). После открытия проверяется цена ликвидации: расстояние до неё должно быть не меньше 1,5 × расстояния до стопа.

**Журнал исполнения.** Записываются:

- цена решения (закрытие дневной свечи);
- цена исполнения;
- проскальзывание в б.п.;
- фактическая комиссия из истории исполнений.

## 3. Цикл `tb run --mode demo`

1. **Ожидание.** После 00:00 UTC плюс задержка (по умолчанию 3 минуты) — чтобы дневная свеча точно закрылась.
2. **Обновление данных.** Докачка свечей и фандинга через публичный клиент T001. Раз в месяц — пересборка вселенной, как в T002.
3. **Решение.** Через тот же `MarketView`, `Strategy` и `portfolio/limits.py`, что в бэктесте. `equity` берётся с биржи.
4. **Сверка.** Если есть расхождение — аварийная остановка.
5. **Исполнение и обновление стопов.**
6. **Журнал и отчёт.**

**Режимы:**

- `--once` — один цикл;
- `--loop` — ожидание до следующего решения в процессе;
- `--dry-run` — печатает заявки и стопы, ничего не отправляя.

**Пропущенное решение.** Если процесс был выключен в момент решения, при запуске цикл выполняется сразу по последней закрытой свече и помечается как запоздавший. Два решения за один день не выполняются.

**Теневая симуляция.** Каждое решение параллельно исполняется в `SimExecutor` по цене решения. Расхождение фактического и симулированного исполнения записывается — это материал для T006b.

## 4. Журнал, уведомления, остановка

**Журнал** в `data/live/demo/`, по файлу на тип, дописываются строками JSON:

- решения;
- заявки;
- исполнения;
- снимки позиций;
- дневной капитал;
- события аварийной остановки.

Запись атомарная построчно.

**Telegram.** Уведомления через Bot API вызовами `httpx`, без новых зависимостей. Токен и chat id — в переменных окружения.

Когда отправляются:

- ежедневная сводка: капитал, позиции, стопы, заявки дня;
- каждое исполнение;
- ошибки;
- аварийная остановка.

Если Telegram недоступен, торговля не останавливается, а ошибка пишется в журнал.

**Аварийная остановка:**

- отменяет все заявки бота на вход;
- не трогает стопы на бирже;
- пишет флаг остановки.

Возобновление — только командой `tb run resume` после чтения причины и подтверждения в консоли.

## 5. Предстартовая проверка `tb demo check`

Без единой заявки проверяет:

- подпись и авторизацию;
- тип счёта и баланс;
- синхронизацию часов;
- права ключа (нет права вывода, если эндпоинт позволяет это узнать);
- отсутствие чужих позиций и заявок;
- доступность публичных данных и свежесть кэша;
- снимок инструментов;
- тестовое сообщение в Telegram;
- что режим `demo`, а адрес не основной сети.

## Тесты (без сети, на `MockTransport`)

- **Подпись:** на фиксированных ключе, времени и параметрах — ожидаемая строка; пример из документации, если он там есть.
- **Идемпотентность:** таймаут → запрос по `orderLinkId` → без дубля заявки.
- **Разница целей:** считается от биржевых позиций; округление и сокращения по правилам T003.
- **Стоп:**
  - после исполнения выставлен и подтверждён;
  - не подтверждён за 60 секунд → закрытие по рынку и остановка;
  - не ослабляется при обновлении.
- **Ликвидация:** цена ликвидации слишком близко → уменьшение позиции.
- **Сверка:** расхождение → остановка без заявок; чужая позиция → отказ старта.
- **Пропущенное решение:** запоздавший цикл выполняется один раз и помечается.
- **Аварийная остановка:** каждое условие из таблицы в пункте 0; возобновление только через `resume`.
- **Запрет основной сети и режима `live`.**
- **Единый код с бэктестом:** решение цикла на исторической дате совпадает с решением бэктеста V1x на ту же дату при одинаковом капитале.

## Критерии готовности

1. Все проверки из `CLAUDE.md` зелёные; CI зелёный на обеих ОС.
2. Коммит с решениями пункта 0 сделан до реализации. `T006-risk-level.json` посчитан только по `dev`/`val`.
3. `tb demo check` проходит на реальном Demo-счёте владельца.
4. `tb run --mode demo --once --dry-run` показывает заявки и стопы, согласованные с бэктестом.
5. Один реальный цикл на Demo:
   - заявки исполнены;
   - стопы на бирже подтверждены;
   - журнал и сообщение в Telegram на месте;
   - теневая симуляция записана.
6. Отчёт по задаче:
   - выбранный уровень риска;
   - просадки при нём на `dev` и `val`;
   - пропуски на $1000;
   - расхождения с документацией Bybit;
   - результат первого реального цикла.
