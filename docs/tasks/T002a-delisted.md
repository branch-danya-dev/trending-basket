# T002a — делистингованные инструменты во вселенной

## Контекст

Прочитай `CLAUDE.md` и `docs/DECISIONS.md`. T002 смержен: вселенная строится из текущих символов со статусом `Trading`, ошибка выжившего отмечена в метаданных.

При проверке выяснилось, что `GET /v5/market/instruments-info` с `status=Closed` возвращает закрытые инструменты. Значит, часть ошибки выжившего можно убрать: монеты, удалённые с биржи, должны попадать в прошлые составы вселенной так же, как попадали бы в реальности.

Цель задачи — включить закрытые инструменты в пул кандидатов с учётом момента закрытия и дать бэктесту (T003) способ узнать, торговался ли символ в заданный момент.

## Git

Ветка `task/002a-delisted`, PR в `main`. Готово, когда CI зелёный на Ubuntu и Windows.

## Что сделать

### 1. Снимок инструментов со всеми статусами

`tb data sync instruments` сохраняет в снимок инструменты всех статусов, которые API отдаёт для `category=linear`: как минимум `Trading` и `Closed`, плюс другие статусы, если найдутся. Поле `status` хранится в снимке.

В отчёте перечисли:

- какие статусы встретились и сколько инструментов каждого;
- какие поля заполнены у закрытых инструментов, в частности есть ли у них время закрытия (`deliveryTime` или другое поле).

### 2. Загрузка свечей закрытых символов

Попробуй `tb data sync klines` для закрытых `LinearPerpetual` USDT-символов с 2021-01-01. В отчёте:

- сколько закрытых символов прошло фильтры пула;
- у скольких API вернул историю свечей, у скольких — пусто или ошибку;
- для 5 закрытых символов с наибольшим оборотом: даты первой и последней свечи и время закрытия из снимка, если оно есть.

Символы без доступной истории не ломают сборку, а перечисляются отдельно.

### 3. Пул кандидатов и момент окончания торговли

`tb universe candidates` включает закрытые `LinearPerpetual` USDT-символы с теми же исключениями, что и для торгующихся.

Для каждого символа определяется `listed_until_ms`:

- время закрытия из снимка, если поле есть и заполнено;
- иначе время закрытия последней доступной свечи;
- для торгующихся — пусто.

Источник значения сохраняется в отдельной колонке.

### 4. Отбор без заглядывания вперёд

На дату пересборки `d` символ допускается, только если он торговался в момент `d`: `listed_until_ms` пусто или больше `d`, плюс все прежние условия T002. Будущий делистинг не должен влиять на отбор на `d`: символ, закрытый через месяц после `d`, на дату `d` допускается на общих основаниях.

Новая функция `is_tradeable_at(symbol, time_ms) -> bool` для бэктеста. Возвращает `False`, если `time_ms` раньше первой свечи или не раньше `listed_until_ms`. Бэктест в T003 будет с её помощью:

- принудительно закрывать позицию, если символ перестал торговаться в середине месяца;
- запрещать новые входы в закрытый символ.

### 5. Метаданные и отчёт

Флаг `survivorship_bias` в `meta.json` меняется с `true` на объект:

```json
{
  "delisted_included": 0,
  "delisted_without_history": 0,
  "note": "..."
}
```

Числа — фактические, `note` описывает, что осталось неустранённым: например, символы без истории и инструменты, которые API не отдаёт вообще.

`tb universe report` дополнительно показывает, в какие месяцы в составе были символы, позже закрытые, и какие именно.

## Тесты (без сети, на синтетических данных)

- Символ, закрытый после `d`, допускается на `d`. Закрытый до `d` — нет. Закрытый ровно в `d` — нет.
- Изменение `listed_until_ms` на время после `d` не меняет состав на `d`.
- `is_tradeable_at`: до первой свечи, внутри истории, ровно в `listed_until_ms`, после.
- Определение `listed_until_ms` из снимка и из последней свечи с правильной пометкой источника.
- Закрытый символ без истории свечей не ломает сборку и попадает в отчёт.
- Повторная сборка даёт идентичный parquet.

## Вне рамок задачи

Бэктест и логика принудительного закрытия позиций (T003), данные других бирж, автоматизация снимков.

## Критерии готовности

1. Все проверки из `CLAUDE.md` зелёные; CI зелёный на обеих ОС.
2. Ручная проверка владельцем на реальных данных:
   ```
   uv run tb data sync instruments
   uv run tb universe candidates --out data/universe/candidates.txt
   uv run tb data sync klines --symbols-file data/universe/candidates.txt --interval 1d --since 2021-01-01
   uv run tb universe build --name core15 --since 2021-01-01
   uv run tb universe report core15
   ```
3. В отчёте по задаче — числа из пунктов 1, 2 и 5 и сравнение с T002: сколько записей состава изменилось и в каких месяцах.
4. `docs/DECISIONS.md` дополнен решением о включении закрытых инструментов и правиле определения `listed_until_ms`.
