# T004 — трендовая корзина v0

## Контекст

Прочитай `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`. T003 смержен: бэктест-движок, эталоны, лимиты на фактических позициях, фандинг по восстановленным интервалам.

Задача — первая трендовая стратегия и её прогон на **периоде разработки**. Параметры не подбираются по нашим данным: берутся классические значения семейства пробойных трендовых систем и фиксируются заранее. Варианты для сравнения тоже заданы заранее, в этом файле.

Решение «работает / не работает» здесь не принимается. Это задача T005 на валидационном и отложенном периодах.

## 1. Разбиение периодов — зафиксировать до любого прогона стратегии

Первый коммит задачи — запись в `docs/DECISIONS.md`:

| Период | Даты (UTC) | Назначение |
|---|---|---|
| Разогрев | 2021-01-01 — 2021-10-31 | Только история для индикаторов, сделки не оцениваются |
| Разработка (dev) | 2021-11-01 — 2024-06-30 | Прогоны T004, любые исследования |
| Валидация (val) | 2024-07-01 — 2025-09-30 | Выбор варианта в T005 |
| Отложенный (holdout) | 2025-10-01 — последняя закрытая дата | Одна финальная проверка в T005 |

### Защита периодов в коде

- В TOML эксперимента обязательное поле `period = "dev" | "val" | "holdout" | "full"`. Даты `start`/`end` берутся из таблицы выше, а не задаются вручную.
- Эталоны (`buy_and_hold_btc`, `equal_weight_universe`) можно запускать на любом периоде.
- Любая другая стратегия запускается на `val` только с флагом `--allow-val`. На `holdout` и `full` — только с флагом `--allow-holdout` и подтверждением в консоли.
- Каждый запуск стратегии на `val`, `holdout` и `full` дописывается в `reports/period-access-log.jsonl`: время, эксперимент, commit, период.
- Тест: запуск стратегии на `val`/`holdout` без флага завершается ошибкой; журнал пополняется при запуске с флагом.

## 2. Эталоны без лимитов стратегии

Эталон `buy_and_hold_btc` должен быть чистым держанием. В его TOML лимиты экспозиции отключены или заданы с запасом, чтобы движок не подрезал позицию, когда фандинг уменьшает капитал.

В отчёте PR приведи разложение итогового капитала эталона BTC до и после этой правки:

- ценовой PnL;
- уплаченный и полученный фандинг;

- число подрезаний.

Объясни, почему результат T003 изменился между прогонами с −5,55% на +2,47%.

## 3. Стратегия `strategies/trend_basket.py`

Параметры — pydantic-модель, значения по умолчанию ниже. В `docs/DECISIONS.md` они записываются как классические значения пробойных систем, не подобранные на наших данных.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `lookbacks_days` | [20, 55, 100] | Горизонты подсистем |
| `exit_ratio` | 0.5 | Выход подсистемы — по каналу длиной `L × exit_ratio` |
| `atr_days` | 20 | Период ATR по дневным свечам |
| `stop_atr_mult` | 3.0 | Ширина трейлинг-стопа в ATR |
| `risk_per_symbol_frac` | 0.005 | Риск на символ при полном сигнале, доля капитала |
| `rebalance_band_frac` | 0.25 | Минимальное относительное изменение цели для перебалансировки |
| `direction` | `long_only` | `long_only` или `long_short` |

### Сигнал

Для каждого символа и каждого `L` — подсистема с состоянием −1, 0 или +1:

- **Вход в лонг:** закрытие бара выше максимума `high` предыдущих `L` дней, текущий бар не включается.
- **Выход из лонга:** закрытие ниже минимума `low` предыдущих `L × exit_ratio` дней.
- **Шорт** — зеркально, только в режиме `long_short`. При `long_only` отрицательные состояния не открываются.

Итоговый сигнал символа `f` — среднее состояний подсистем, от −1 до +1 с шагом 1/3.

### Размер

```
ATR_frac      = ATR(atr_days, дневные свечи) / close
full_notional = risk_per_symbol_frac × equity / (stop_atr_mult × ATR_frac)
target        = f × full_notional
```

Цель меняется, только если:

- изменился знак или значение `f`;
- или относительное изменение `|target − current| / |current|` превышает `rebalance_band_frac`.

Иначе позиция остаётся прежней, чтобы не платить комиссии за мелкие колебания ATR.

### Стоп

Один трейлинг-стоп на позицию символа, передаётся в `TargetPosition.stop_price`:

```
лонг:  stop = max(предыдущий stop, максимальное закрытие с момента открытия − stop_atr_mult × ATR)
шорт:  зеркально
```

Стоп никогда не ослабляется.

После срабатывания стопа все подсистемы символа сбрасываются в 0. Новый вход возможен только по новому пробою: закрытию, которое случилось после стопа и выполняет условие входа какой-либо подсистемы.

`initial_risk_usd` на открытии равен `|target| × stop_atr_mult × ATR_frac`. При увеличении позиции в R-статистике используется максимальный риск за жизненный цикл.

### Вселенная

- Новые входы — только в символах из `universe_at(t)`.
- `exit_on_universe_removal = false`: позиция в выбывшем символе ведётся до выхода по сигналу или стопу, без увеличения.

### Вариант 4h

Решения принимаются на закрытии каждого 4-часового бара.

- Каналы считаются по 4h-свечам с длинами `L × 6`.
- ATR — по дневным свечам: последняя закрытая дневная, без заглядывания вперёд.
- Стоп — тот же `stop_atr_mult × ATR_1d`.

От дневного варианта отличается только частота решений и точность каналов, риск на позицию сопоставим.

## Тесты (без сети, на синтетических рядах)

- Пробой определяется по предыдущим `L` барам без текущего; тест на отсутствие заглядывания вперёд.
- На растущем ряде подсистемы включаются по очереди, `f` растёт по 1/3; на падающем при `long_only` позиции нет.
- Стоп не ослабляется ни при каких входных данных.
- После стопа повторный вход только по новому пробою.
- Полоса перебалансировки: мелкие изменения ATR не порождают заявок.
- Формула размера и `initial_risk_usd` — ручной пример.
- Вариант 4h использует только закрытые дневные свечи для ATR.
- Защита периодов и журнал доступа.
- Детерминизм: повторный прогон V1 даёт идентичные parquet.
