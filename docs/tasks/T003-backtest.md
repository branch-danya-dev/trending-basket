# T003 — бэктест-движок

## Контекст

Прочитай `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`. Готово:

- **T001** — кэш свечей, фандинга и инструментов;
- **T002** — вселенная по месяцам и `universe_at`;
- **T002a** — закрытые инструменты и `is_tradeable_at`.

Задача — движок, который честно считает результат любой стратегии на истории: исполнение без заглядывания вперёд, комиссии, проскальзывание, исторический фандинг, стопы внутри свечи, округление по параметрам инструментов, принудительное закрытие при делистинге.

Трендовой стратегии здесь нет, это T004. Для проверки движка — две эталонные стратегии: держание BTC и равновесная корзина вселенной.

Интерфейсы проектируются так, чтобы в T006 тот же код стратегии и портфельных лимитов работал с живым исполнением. Меняется только исполнитель.

## Подготовка данных (владелец, до ручной проверки)

Добавь команду `tb universe members NAME --out PATH`: объединение всех символов, когда-либо входивших во вселенную. По этому списку владелец докачивает данные:

```
uv run tb universe members core15 --out data/universe/core15-members.txt
uv run tb data sync funding --symbols-file data/universe/core15-members.txt --since 2021-01-01
uv run tb data sync klines --symbols-file data/universe/core15-members.txt --interval 4h --since 2021-01-01
```

## Модель времени и исполнения

**Решение.** Стратегия вызывается в момент закрытия бара `t`: для 1d — 00:00 UTC, для 4h — каждые 4 часа. Ей доступны только свечи, закрытые не позже `t`.

**Исполнение.** Изменения позиций исполняются по цене открытия следующего бара с проскальзыванием. Для крипты открытие следующего бара совпадает по времени с закрытием текущего, это честное приближение «исполнил сразу после решения».

**Стопы.** Стратегия задаёт уровень стопа для каждой позиции, движок держит его до следующего решения. На каждом следующем баре:

- если цена открытия уже за стопом (гэп), выход по цене открытия;
- иначе, если `low` (для лонга) или `high` (для шорта) касается стопа, выход по цене стопа.

К цене выхода применяется проскальзывание стопа. Выход по стопу считается taker.

**Делистинг.** Если `is_tradeable_at` становится `False` при открытой позиции, позиция закрывается по последней доступной цене закрытия с отдельным штрафным проскальзыванием `delist_slippage_bps` (по умолчанию 200). Входы в неторгуемые символы запрещены.

**Вселенная.** Открыть или увеличить позицию можно только в символе из `universe_at(t)`. Для позиций в символах, выбывших из вселенной, есть параметр `exit_on_universe_removal`:

- `false` (по умолчанию) — стратегия ведёт позицию до своего выхода;
- `true` — закрыть на ближайшем решении.

## Интерфейсы

### `strategies/base.py`

```python
class Strategy(Protocol):
    name: str

    def decide(self, ctx: DecisionContext) -> Decision: ...
```

`DecisionContext` содержит:

- `time_ms`;
- `equity_usd`;
- текущие позиции (количество, средняя цена входа, текущий стоп, риск на входе);
- `universe` — список символов на `t`;
- `market: MarketView`.

`MarketView` — единственный доступ к данным. Метод `candles(symbol, interval, lookback)` возвращает только свечи, закрытые не позже `t`. Попытка получить что-либо позже `t` невозможна по устройству класса.

`Decision` — словарь `symbol → TargetPosition`:

| Поле | Смысл |
|---|---|
| `notional_usd` | Целевой номинал со знаком: плюс — лонг, минус — шорт |
| `stop_price` | Уровень стопа или `None` |
| `initial_risk_usd` | Риск на входе; задаётся при открытии, нужен для статистики в R |

Символ, отсутствующий в `Decision`, означает целевую позицию 0.

### `portfolio/limits.py`

Применяется между стратегией и исполнением — и в бэктесте, и потом в live.

| Лимит | Параметр | По умолчанию |
|---|---|---|
| Суммарный номинал / капитал | `max_gross_exposure` | 2.0 |
| Чистый номинал / капитал | `max_net_exposure` | 1.5 |
| Номинал одного символа / капитал | `max_symbol_exposure` | 0.5 |

При превышении цели масштабируются пропорционально вниз. Каждое срабатывание записывается в журнал событий.

### Исполнитель `backtest/sim_executor.py`

Разница целей и текущих позиций превращается в заявки:

- количество = номинал / цена исполнения;
- округление к нулю по `qtyStep` из снимка инструментов (для закрытых — из их записи);
- если меньше `minOrderQty` или `minNotionalValue`, заявка пропускается, пропуск записывается.

Параметры инструментов берутся из последнего снимка: исторические значения API не отдаёт. Это допущение записывается в отчёт.

Комиссии — по типу исполнения:

- изменения позиций на решении — `taker` по умолчанию, параметр `rebalance_fill = taker | maker`;
- стопы и делистинг — всегда `taker`.

### Фандинг

На каждый момент фандинга из истории символа при открытой позиции:

```
payment_usd = − quantity × price × rate_frac
```

Лонг платит при положительной ставке, шорт получает.

Цена берётся по приоритету:

1. открытие 4h-свечи, начинающейся в момент фандинга (времена фандинга совпадают с границами 4h);
2. иначе открытие дневной свечи, внутри которой фандинг;
3. источник цены записывается.

Отсутствующая запись фандинга считается нулём, но учитывается в метрике покрытия фандингом. Покрытие ниже 99% — предупреждение в отчёте.

### Учёт

Для каждой позиции: количество, средняя цена входа, реализованный PnL. На закрытии каждого бара:

```
equity = initial_capital + реализованный PnL + нереализованный PnL − комиссии − проскальзывание ± фандинг
```

Тождество проверяется на каждом баре внутри движка, расхождение больше 1e-6 — ошибка.

**Жизненный цикл позиции** — от открытия из нуля до возврата в ноль. По каждой закрытой позиции записываются:

- время входа и выхода;
- причина выхода: сигнал, стоп, делистинг, выбытие из вселенной, лимит;
- PnL до и после издержек;
- комиссии и фандинг;
- результат в R, если задан `initial_risk_usd`.

## Эталонные стратегии `strategies/benchmarks.py`

- `buy_and_hold_btc` — лонг BTCUSDT на весь капитал с первого решения, без стопа, с фандингом.
- `equal_weight_universe` — равные доли капитала на символы вселенной, ребалансировка при каждой пересборке вселенной, суммарно 1x, без стопов.

Отдельно в отчёте — ценовая доходность BTC без фандинга и издержек, как самый простой ориентир.

## Эксперименты и отчёты

Эксперимент описывается TOML-файлом в `experiments/` (читается стандартным `tomllib`), файл коммитится:

```toml
[run]
name = "bh_btc"
strategy = "buy_and_hold_btc"
universe = "core15"
interval = "1d"
start = "2021-11-01"
end = "2026-09-27"
initial_capital_usd = 1000

[costs]
taker_fee_bps = 5.5
maker_fee_bps = 2.0
slippage_bps = 2.0
stop_slippage_bps = 5.0
delist_slippage_bps = 200.0
rebalance_fill = "taker"

[limits]
max_gross_exposure = 2.0
max_net_exposure = 1.5
max_symbol_exposure = 1.0   # для эталона BTC; у трендовой корзины по умолчанию 0.5
exit_on_universe_removal = false

[strategy_params]
```

`tb backtest run experiments/bh_btc.toml` создаёт `reports/{name}-{YYYYMMDDTHHMMSSZ}/`. Время берётся через `Clock`, запись атомарная.

| Файл | Содержимое |
|---|---|
| `fills.parquet` | Каждое исполнение: время, символ, сторона, количество, цена, комиссия, проскальзывание, причина |
| `positions.parquet` | Жизненные циклы позиций, как описано выше |
| `equity.parquet` | По барам: капитал, реализованный и нереализованный PnL, накопленные комиссии, проскальзывание и фандинг, суммарная и чистая экспозиция, число позиций |
| `events.parquet` | Срабатывания лимитов, пропуски по минимальному размеру, делистинги, предупреждения |
| `metrics.json` | Метрики ниже |
| `manifest.json` | Копия TOML, git commit, диапазоны и число строк входных файлов, снимок инструментов, версия пакета |
| `report.md` | Сводные таблицы |
| `equity.png`, `drawdown.png` | Графики (`matplotlib` — новая зависимость, обосновать в PR) |

**Метрики** (дневные доходности, годовой пересчёт по 365 дням):

- итоговая доходность, CAGR, годовая волатильность;
- Sharpe (без безрисковой ставки), Sortino;
- максимальная просадка и её длительность, Calmar;
- годовой оборот;
- комиссии, проскальзывание и фандинг в долларах и в процентах от валовой прибыли;
- число позиций, доля прибыльных, средние выигрыш и проигрыш в R;
- средняя и максимальная суммарная и чистая экспозиция;
- покрытие фандингом;
- число пропусков по минимальному размеру;
- разбивка результата по годам и по символам.

`tb backtest show RUN_DIR` печатает метрики. `tb backtest compare RUN_DIR RUN_DIR ...` — таблицу метрик рядом.

## Тесты (без сети)

1. **Ручной пример.** Один символ, 4 бара, известные цены, комиссии, проскальзывание, одна запись фандинга. Вход на открытии бара 2, стоп касается на баре 4. Итоговый капитал, комиссии и фандинг сходятся с ручным расчётом до 1e-9. Расчёт приведён в комментарии теста.
2. **Гэп через стоп** → выход по открытию, а не по стопу. Касание стопа → выход по стопу с проскальзыванием. Шорт — зеркально.
3. **Фандинг:** лонг платит и шорт получает при положительной ставке; выбор цены из 4h и запасной вариант из 1d; учёт покрытия.
4. **Заглядывание вперёд:**
   - `MarketView` не отдаёт свечи после `t`;
   - изменение всех данных после момента `T` не меняет ни одного исполнения и значения капитала до `T`.
5. **Делистинг:** принудительное закрытие со штрафом; запрет входа.
6. **Вселенная:** вход вне `universe_at` отклоняется; оба режима `exit_on_universe_removal`.
7. **Округление:** к нулю по шагу; пропуск ниже минимума записывается.
8. **Лимиты:** пропорциональное масштабирование по каждому из трёх лимитов.
9. **Учёт:** тождество капитала на каждом баре; учёт частичных уменьшений и переворота позиции через ноль.
10. **Эталоны:** `buy_and_hold_btc` на синтетическом инструменте с мелким шагом количества, без издержек и фандинга, даёт ровно ценовую доходность BTC. На реальных данных при $1000 округление по шагу BTC оставит часть капитала в кэше — это ожидаемо и попадает в отчёт.
11. **Детерминизм:** два прогона одного TOML дают идентичные parquet и `metrics.json`, кроме времени создания в manifest.
12. **Скорость:** 5 лет дневных данных по 30 символам с тривиальной стратегией — не дольше нескольких секунд на обычном ПК.
