# T002 — отчёт о вселенной символов

Проверено на Windows 2026-09-29 по Москве (2026-09-28 UTC).
Реальный API: `https://api.bybit.com`. Коммит реализации: `8e4024083699da0b7092a68755a0a26e1d2dc93f`.
T001 закрыт merge PR #3 (`b4781cb`) после CI на Ubuntu и Windows;
полная страница 1000 свечей и стык страниц покрыты отдельным тестом.

## Что сделано

- Добавлены `tb universe candidates`, `build`, `report`, `show` и интерфейс
  `load_universe(data_dir, name).universe_at(time_ms)` для T003.
- Отбор ежемесячный: максимум 15 символов, 120 наблюдаемых дневных свечей,
  медиана оборота за полные 30 дней от 10 млн USD (USDT используется как USD-прокси).
  Используются только свечи с `open_time_ms + DAY_MS <= rebalance_time_ms`.
  Параметры и причины выбора записаны в ADR-007–009.
- Снимок инструментов расширен полями классификации. Старые снимки без них
  требуют `tb data sync instruments`; это предотвращает молчаливое включение акций.
- Parquet и JSON публикуются через временные файлы и атомарную замену каждого.
  Сбой между двумя заменами обнаруживается по SHA-256. В metadata сохраняются
  параметры, Clock timestamp, commit, снимок, исключения и все входные кэши.

## Реальный пул и ограничения

Снимок `2026-09-28.parquet` содержит **886 инструментов, все со статусом Trading**.
Из них 778 — USDT LinearPerpetual. После удаления классов некриптовых активов
осталось 521; 5 стейблкоинов и 2 токена золота исключены CSV-файлом.
Итог: **514 кандидатов**. Отсутствующих файлов кэша — 0;
513 содержат свечи. KIIUSDT появился 28 сентября и пока
не имеет закрытой дневной свечи; пустой кэш корректно не допускает его в состав.

С 2021-01-01 есть непрерывная история у **5** кандидатов:
BCHUSDT, BTCUSDT, LINKUSDT, LTCUSDT, XTZUSDT.
Если считать любое начало внутри 2021 года, таких кандидатов **78**.
Общий `tb data check` по 514 кандидатам завершился кодом 0, без пропусков
в имеющихся диапазонах и без ошибок валидации.

Правило классификации: `symbolType` пустой или `innovation`, одновременно
пустые `marketRegion` и `underlyingTicker`. Неизвестные типы исключаются до проверки.
В реальном снимке присутствовали `stock` (196), `ETF` (54), `commodity` (4),
`forex` (3). Они исключены по полям, а не по фрагментам имён. PAXG и XAUT
приходят с пустым `symbolType`, поэтому явно исключены как токенизированное золото.
Список стейблкоинов в `config/universe_exclusions.csv` требует сопровождения
при появлении новых активов.

**Ошибка выжившего подтверждена для используемого пула.** В обычном снимке
нет Closed. Однако утверждение, что API вообще не возвращает делистинги,
не подтвердилось: отдельный запрос
`GET /v5/market/instruments-info?category=linear&status=Closed&limit=1000`
вернул на первой странице 995 Closed и 5 PendingOpen с непустым курсором.
Примеры Closed: 10000000AIDOGEUSDT, 1000000CHEEMSUSDT, 1000000PEIPEIUSDT.
Это наблюдение первой страницы, не оценка полного числа делистингов.

По рамкам задачи эти инструменты не добавляются в текущий пул, исторические
листинги не восстанавливаются. Поэтому metadata содержит `survivorship_bias=true`,
`snapshot_contains_closed=false`, статусы снимка и пояснение ограничения.
Отбор свечей без будущего не устраняет смещение сегодняшнего пула; будущий
бэктест может завышать результаты. Топ по ликвидности не гарантирует отсутствие смещения.

## Как проверить

Из корня репозитория, PowerShell:

```powershell
uv sync --locked
uv run tb data sync instruments
uv run tb universe candidates --out data/universe/candidates.txt
uv run tb data sync klines --symbols-file data/universe/candidates.txt --interval 1d --since 2021-01-01
uv run tb data check --symbols-file data/universe/candidates.txt --interval 1d
uv run tb universe build --name core15 --since 2021-01-01
uv run tb universe report core15
uv run tb universe show core15 --at 2024-03-01
```

Все команды выполнены на реальной сети/кэше с кодом выхода 0. Дополнительно
выполнены `show` на 2021-06-01 и 2026-09-01 и повторный `build`.
Результаты сохранены локально в `reports/t002-sync-klines.log`,
`reports/t002-validation.json`, `reports/t002-audit-summary.json`.

Повторный build дал побайтно одинаковый parquet:
`a794fbe7b26c5e3e580a6f32d3ad6c6162a7136b54b7cfd96bd1ca00940f0a51`.

Локальные проверки:

| Команда | Результат |
|---|---|
| `uv run ruff check .` | успешно |
| `uv run ruff format --check .` | успешно |
| `uv run mypy src` | 21 файл, без ошибок |
| `uv run pytest` | 117 passed, без сети |

Тесты проверяют будущие свечи, включая невалидные значения после границы,
закрытие точно на пересборке, короткую историю, пропуски внутри окна и в его
конце, оборот, медиану против всплеска, равные значения, малый/пустой состав,
чтение пустого месяца без переноса прежнего состава, CSV-исключения,
классификацию инструментов, сохранение полей в кэше, CLI, повторяемость parquet,
сбой подготовки и обнаружение прерванной публикации двух файлов.

## Что сознательно не сделано

Восстановление делистингов и исторической классификации активов, автоматизация
снимков, торговая стратегия, бэктест и спотовые данные. Сохранилась текущая
модель одной записи вселенной за раз; параллельный build одного имени не поддерживается.
На момент этого отчёта T002 ещё не смержен; текущий CI проверяется в PR.
