# Самостоятельный запуск Demo на Windows

Откройте PowerShell в каталоге репозитория. Настройки уже находятся в локальном
`.env`: Demo, ключи, Telegram и `TB_ALLOCATED_CAPITAL_USD=1000`.

После T006a2 нужен именованный прогон. Для однократного переноса существующей
книги T006a без закрытия позиции и сброса капитала:

```powershell
.\.venv\Scripts\tb.exe run start --name demo-001 --adopt-legacy
```

Повторять start при перезапусках не нужно. Для нового пустого прогона используется
`run start --name demo-002` после закрытия предыдущего командой `run close`.

## Обычный запуск или восстановление после выключения компьютера

```powershell
.\.venv\Scripts\tb.exe run verify
.\.venv\Scripts\tb.exe run --mode demo --loop
```

Оставьте окно и компьютер включёнными. Процесс сверяет позиции, стопы и маржу
между ежедневными решениями. После пропущенного времени обработает последнее
дневное закрытие; уже завершённый день повторно не торгует. Вторая копия
на этом компьютере не запустится из-за блокировки. Не запускайте независимые
копии бота с одним ключом и разными каталогами состояния на разных устройствах.

## Если установлен флаг аварийной остановки

Сначала устраните указанную причину. Затем:

```powershell
.\.venv\Scripts\tb.exe run resume
.\.venv\Scripts\tb.exe run --mode demo --loop
```

Первая команда покажет причину, попросит подтверждение и выполнит сверку.
Если сверка или контроль риска не проходят, возобновление будет отклонено.
Удалять `data/live/demo/state.json`, сбрасывать пик или менять выделенный
капитал для обхода остановки нельзя. Для этих команд сообщения в чат не нужны.

## Проверка без торговых заявок

```powershell
.\.venv\Scripts\tb.exe demo check
.\.venv\Scripts\tb.exe run --mode demo --once --dry-run
```

`demo check` отправляет проверочное сообщение в Telegram. Dry-run не отправляет
заявки или сообщения и не меняет торговое состояние.

`--once` выполняет один цикл и завершает процесс. Биржевой стоп остаётся,
но ежедневное сопровождение требует работающего `--loop`. Ctrl+C останавливает
процесс; позиция автоматически не закрывается, подтверждённый стоп остаётся.
Все времена решений — UTC: после 00:03 (03:03 по Москве).

## Контроль непрерывности и автозапуск

`run verify` возвращает код 0 только при согласованном журнале, капитале,
позициях/стопах и независимо пересчитанном состоянии стратегии. Перезапуск после
сети, света или сна не сбрасывает T006b при успешной проверке и отсутствии ручных
торговых действий. Суммарный простой и число перезапусков записываются в сводку.

Автоматическая полнота ограничена 23 ч 55 мин (ADR-022). При большем простое
новые заявки блокируются. После ручной проверки `run verify --accept-gap`
сохранит отметку о неполноте и сбросит отсчёт T006b; расхождение позиции или
капитала эта команда не разрешает. При существенном обновлении кода добавьте
`--allow-code-change` к verify или запуску; изменения попадут в журнал.

```powershell
.\.venv\Scripts\tb.exe service install-windows --dry-run
.\.venv\Scripts\tb.exe service install-windows
```

Вторая команда запросит подтверждение. Автозапуск действует при входе текущего
пользователя в Windows, с повтором после сбоя процесса. Логи — `data/live/demo/logs/`.
Удаление: `tb service uninstall-windows`. Сон при питании от сети рекомендуется
отключить. Перезагрузку и отключение адаптера для испытаний T006a2 выполняйте
после сохранения работы в остальных приложениях.
