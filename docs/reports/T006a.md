## Зафиксированный риск

Первый коммит `100a6bf` содержит ADR-018 и текст задачи, сделан до кода и
прогонов. Код расчёта — `862f441`, результат — `76c8919`; оба отправлены
в GitHub до реализации исполнения. Источник чисел и хеши входов:
[T006-risk-level.json](T006-risk-level.json).

Объединены дневные доходности исходных exact $10000 V1x dev и val.
Волатильность 8,835594%; риск:
`floor(min(0.01, 0.005 * 0.12 / 0.08835593848) / 0.0005) * 0.0005 = 0.0065`.
Принято **0,65% на символ**. Единственные контрольные прогоны:

| Период и режим | Капитал | Доходность | Годовая волатильность | Sharpe | Max DD | Пропуски минимумов | Средний номинал позиции |
|---|---:|---:|---:|---:|---:|---:|---:|
| dev exact | $10000 | −4,465% | 10,880% | −0,103 | −13,397% | 0 | $216,94 |
| val exact | $10000 | +4,314% | 12,548% | 0,332 | −10,644% | 0 | $262,77 |
| val exchange | $1000 | +3,634% | 10,455% | 0,325 | −9,002% | 783 | $21,49 |

Средний номинал — среднее непустой позиции на закрытиях баров, не средняя
заявка. Целевые 12% не достигаются ровно из-за дискретного риска, ограничений
и нелинейности изменения позиций. Повторного подбора не было. Holdout не читался
для расчёта риска и не запускался повторно.

Порог остановки от пика капитала:
`max(1.5 * 0.1339650933058648, 0.15) = 20.094763995879722%`.
Превышение строгое; пик сохраняется между запусками. Лимиты gross/net/symbol
остались 2/1,5/0,5. Критерии T006b записаны в ADR-018 до этой реализации.

## Реализация

- HMAC-подпись фактической строки GET/JSON POST, синхронизация времени,
  `recv_window=5000`; только точный `https://api-demo.bybit.com` и `TB_MODE=demo`.
  Перенаправления выключены. Основная сеть и Testnet приватному клиенту запрещены.
- Намерение заявки сохраняется до отправки. `orderLinkId` зависит от UTC-дня,
  символа и номера операции; после таймаута сначала поиск на бирже. Частичные
  IOC-исполнения учитываются по фактическим fills; недоисполненная часть
  завершённой IOC не отправляется повторно после перезапуска.
- Цель округляется по свежим qtyStep/minOrderQty/minNotionalValue/maxMktOrderQty;
  сокращения — reduceOnly, включая полное закрытие. После сделок проверяются
  лимиты по фактическому капиталу и markPrice; превышения сокращаются с журналом.
- Полный LastPrice-стоп передаётся уже при входе, затем устанавливается/проверяется
  после каждого изменения позиции. Подтверждаются позиция и соответствующая
  условная заявка на полный размер. Стоп не ослабляется. Через 60 секунд без
  подтверждения — аварийное reduceOnly-закрытие и остановка. Защитное закрытие
  не блокируется флагом пяти ошибок; новые входы блокируются.
- Восстановление сверяет историю исполнений за доступное окно с дедупликацией
  execId, фактические позиции, все открытые заявки, другие рынки счёта. Неизвестные
  позиции/заявки не присваиваются боту. Системный stop ID восстанавливается только
  при совпадении с сохранённым намерением полного стопа и параметрами биржи.
- Решения принимает существующий `TrendBasket` через существующий `MarketView`;
  лимиты — существующий `portfolio/limits.py`. Состояния каналов/ATR и реальные
  стоп-выходы сохраняются. Один закрытый UTC-день исполняется один раз; пропущенные
  дни отмечаются, вчерашнее неотправленное намерение автоматически не исполняется.
- `demo-core15` сохраняет отдельную ежемесячную вселенную для исполнения.
  Кэш обновляется публичным клиентом T001; стратегии недоступны незакрытые свечи.
- Shadow через `SimExecutor` сохраняется вместе с решением, до заявок. Журнал
  сравнения содержит реальные/симулированные fills и разницы количества, цены,
  комиссий по символу/стороне. Dry-run использует копию состояния и блокирует
  любые изменяющие запросы непосредственно в клиенте.
- JSONL записывается одним append с fsync; checkpoint — через атомарную замену.
  Блокировка процесса работает на Windows и Linux. Telegram недоступен — событие
  в журнале, торговый цикл из-за этого не прерывается. Секреты/заголовки не пишутся.

## Документация API и ограничения

[Demo API](https://bybit-exchange.github.io/docs/v5/demo) поддерживает нужные REST
операции и `/v5/user/query-api` на Demo-домене. Общие примеры отдельных страниц
с основным доменом не используются. Demo хранит заявки семь дней: после более
длительного простоя автоматическая сверка отказывается утверждать полноту.

[Создание заявки](https://bybit-exchange.github.io/docs/v5/order/create-order)
подтверждает приём асинхронно; рыночная заявка исполняется как IOC и может быть
частичной. Поэтому одного успешного POST недостаточно. Для поиска используется
сначала [realtime](https://bybit-exchange.github.io/docs/v5/order/open-order),
затем история. `110043` при неизменном плече и `34040` при неизменном стопе
обрабатываются как отсутствие требуемого изменения, а не как исполнение.

[Стоп позиции](https://bybit-exchange.github.io/docs/v5/position/trading-stop)
создаёт системную условную заявку. При Full её количество меняется вместе с
позицией. Код дополнительно сверяет side, reduceOnly, triggerBy, triggerPrice
и количество. В полях [позиции](https://bybit-exchange.github.io/docs/v5/position)
`liqPrice` может быть пустым; это не нулевая цена. По заранее принятому ADR-018
невозможность подтвердить расстояние приводит к закрытию позиции. Portfolio
margin для этой проверки не допускается. Для входа устанавливается 3x.

[Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage) вызывается
напрямую через уже имеющийся httpx. Новых зависимостей нет.

Сеть/биржа могут сделать закрытие физически недоступным. Код не записывает такое
закрытие как успешное: сохраняет намерение и остановку, сообщает об ошибке.
Неопределённый незавершённый вход сначала отменяется и сверяется; при невозможности
подтвердить отмену новое встречное намерение не заменяет старое вслепую.
После `--once` процесс завершается, стопы остаются на бирже; дальнейший мониторинг
требует работающего `--loop`. В T006a двухнедельный цикл не запускался.

У стоп-выходов журнал раздельно хранит последнее дневное закрытие (`decision_price`)
и цену стопа (`reference_price`), проскальзывание относительно каждой. Движение
от дневного закрытия к стопу нельзя путать с качеством исполнения у стопа.

частичная IOC, crash recovery, недопустимость mainnet/live, округление и лимиты,
стопы/ликвидация, чужие позиции, пять ошибок, время, просадка, подтверждение resume,
dry-run, однократность дня, shadow, совпадение с бэктестом на двух последовательных
исторических датах и неизменность решения при замене будущих свечей.

CI Ubuntu/Windows: ожидается запуск для ветки PR. До закрытия задачи нужны:

1. `uv run tb demo check` на отдельном Demo-счёте владельца.
2. `uv run tb run --mode demo --once --dry-run`, проверка целей и стопов.
3. `uv run tb run --mode demo --once`: fills, подтверждённые стопы, shadow,
   журнал и Telegram; добавить сюда обезличенные факты реального цикла.

Пока эти шаги не выполнены, успешные синтетические тесты не заменяют реального Demo.
